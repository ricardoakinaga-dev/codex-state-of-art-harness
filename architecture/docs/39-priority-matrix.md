# 39 — Priority Matrix

## P0 — foundation / release-blocking

- authority model and one owner per decision;
- task classification by scale/risk/domain;
- adaptive router with no-skill path and negative routing;
- capability/composition contracts;
- verification contract/evidence freshness;
- stop conditions and loop controller;
- telemetry foundation for route/load/tool/cost/retry/quality;
- duplicate `engineering-framework` authority policy and validator;
- security/permission boundary and human-stop semantics.

**P0 exit:** known-bad evals fail; required contract fields are validated; simple/critical routes both behave as intended; no claim of causal improvement without host trace.

## P1 — high leverage

- Codex-native eval harness and fixed routing families;
- narrow broad triggers and resolve specialist collisions;
- modernize verification/framework/TDD/E2E/security contracts;
- provider/tool preflight and fallback;
- context budgets and actual load measurement;
- integrated Directors for engineering, design and research;
- recovery/append-only state and independent review packet.

## P2 — important conditional

- database/migration specialist;
- performance/observability specialist;
- accessibility specialist;
- game-director and asset pipeline;
- media/content provider adapters;
- benchmark dashboards and human evaluation operations.

## P3 — optional polish

- naming/metadata normalization;
- documentation format automation;
- upstream provenance refresh;
- convenience utilities with no new authority or risk reduction.

## Ranking rule

Priorize safety/correctness/data/authority, then valid measurement, user impact/reliability, maintainability, cost and cosmetic polish. Capability value score is an input, not permission to activate or remove.
