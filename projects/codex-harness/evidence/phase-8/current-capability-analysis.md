## What transfers

- Composition over inheritance and compound-component vocabulary are useful
  when the existing stack already supports them.
- State, async loading, controlled forms, error boundaries and responsive
  interaction are appropriate concerns.
- Accessibility examples provide useful prompts for names, keyboard behavior
  and focus, but they are not evidence of runtime behavior.
- Memoization, code splitting and virtualization are conditional techniques,
  not defaults.

## Material gaps for Codex-native frontend engineering

The current skill tells a builder patterns but not how to bind a task,
architecture, authority, stack choice, artifact identity, acceptance criteria,
browser render, state matrix, reviewer role, security handoff, performance
budget, or stop condition. It can therefore produce plausible source code
without making a false visual or accessibility claim detectable.

Its illustrative `fetch` patterns have no cancellation, schema validation,
retry/backoff policy, stale-response protection or request identity. Its
controlled form example does not define server error mapping or double-submit
prevention. Its modal example does not demonstrate a complete focus trap,
restoration or inert background. These are guidance limitations, not claims
that every consumer is broken.

## Routing boundary

The correct activation signal is a material executable frontend surface with a
known repository stack, route/state contract and acceptance criteria. A
technology name alone is insufficient. Frontend engineering is distinct from
visual art direction, factual verification, generic coding standards,
orchestration and final security assurance.
