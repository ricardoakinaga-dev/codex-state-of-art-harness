# Verification Loop vNext Modernization Plan

## Candidate identity

- Capability: `verification-loop-vnext`
- Scope: project-local Codex capability package
- Owner: `VERIFIER` for factual evidence; `lead` owns integration
- Current input: `verification-loop` at `~/.agents/skills/verification-loop`
- Promotion ceiling: `VERIFIED` candidate; no global migration

## Contract delta

| Current debt | vNext boundary |
| --- | --- |
| Frontmatter-only identity | Native `CM-1` manifest with exact identity and provenance |
| Claude/session wording | Host-neutral router with Codex project-local discovery contract |
| Shell commands in prose | Declarative deterministic procedures with read-only and bounded policies |
| One aggregate report | Immutable typed input/output and per-criterion records |
| No artifact lineage | Artifact/evidence refs, digests, versions and stale invalidation |
| No role contract | VERIFIER-only ownership with reviewer/assurance exclusions |
| No stop model | Typed budgets and explicit blocking/no-progress/retry stops |
| No eval package | Fixed positive, negative, stale, security and activation scenarios |
| No benchmark | Native/current/upstream/vNext comparison with context and failure cost visible |

## Profiles

`FOCUSED` checks a small declared claim set; `DOMAIN` adds domain criteria;
`FULL` runs the complete selected suite; `VISUAL` requires current render
evidence but does not judge taste; `STRUCTURAL` checks artifact/schema/runtime
facts; `SECURITY_AWARE` adds trust-boundary and mutation checks;
`COMPOSITION` validates handoffs, role separation, artifact lineage and fresh
final verification. Profiles are overlays, not invitations to load every
reference.

## Activation policy

Activate only when the task requests factual verification, a required gate
needs current evidence, or an explicit composition handoff names the vNext
capability and supplies immutable criteria/artifact identity. Do not activate
for implementation, design direction, visual scoring, repair, research,
orchestration, assurance or release approval. Block on missing identity,
criteria, artifact/evidence, required tool, freshness or authority.

## Implementation slices

1. Immutable models and canonical serialization.
2. Manifest/package validator and profile/role/stop policy.
3. Read-only deterministic procedure adapters and path confinement.
4. Criterion-level verifier and evidence report.
5. Package references, fixtures, eval scenarios and benchmark runner.
6. Phase 3/4 integration, bounded real host pilot and composition adapter.
7. Security, regressions, independent review and exact packet closure.

Every slice must retain the original package, preserve previous freeze files,
and add current evidence rather than rewriting historical records.
