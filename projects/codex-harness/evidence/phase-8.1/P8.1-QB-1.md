# Phase 8.1 Quality Bar — P8.1-QB-1

This bar is frozen before any Phase 8.1 build or runtime repair. It preserves
the Phase 8 bar and adds the closure requirements from the authoritative
Phase 8.1 specification. A waiver can explain an unavailable tool, but never
turns missing evidence into `PASS`.

## Required gates

| ID | Gate | Required current evidence |
| --- | --- | --- |
| P8.1-01 | Authority and preservation | Pasted specification, prior Phase 8 packet, installed/global snapshots and the local feature-freeze scope are identified; global, installed-skill and unrelated-worktree mutations are zero. |
| P8.1-02 | Baseline and identity | Current HEAD, worktree status, source trees, frontend package, verifier package, old/new fingerprint reconciliation and historical Phase 8 inputs are recorded with digests. |
| P8.1-03 | Findings closure | A typed High/Medium/Low ledger has explicit owners, severity semantics, evidence refs and closure status; promotion-blocking High/Medium findings are zero for a promotion claim. |
| P8.1-04 | Host capability matrix | Official supported app-server/session APIs, workspace and observer capabilities are probed and classified as official, host-observed, harness-observed, inferred, unsupported or unknown. |
| P8.1-05 | Composition proof | Either `PROVEN_WITH_HOST_LOAD_EVENT` is bound to an actual supported host-load event, or an independent review accepts `PROVEN_WITH_OBSERVABLE_ALTERNATIVE_CAUSALITY` with exact identity, authorization, workspace, monotonic timeline, source/artifact/browser/verifier/final-verification digests and zero alternate producer/manual mutation. |
| P8.1-06 | Fresh real frontend invocation | The exact current frontend package is authorized and invoked against a bounded local workspace; the invocation, task/run IDs, response, source digest and artifact digest are current and reproducible. |
| P8.1-07 | Runtime/browser matrix | Real browser observations cover 1440×900, 1024×768, 768×1024 and 390×844, with overflow, CTA, form, labels, controls and loading/success/error state assertions plus bound screenshots/console/network metadata. |
| P8.1-08 | Runtime interactions | Blank submit, invalid, valid, submitting, success, server failure, retry, duplicate/idempotent retry, keyboard submit, stale response, URL state/back-forward, focus/keyboard and bounded touch/zoom/reduced-motion behavior are observed or explicitly N/A with rationale. |
| P8.1-09 | Accessibility runtime | Labels/names, heading order, keyboard traversal, focus visibility, error association, live regions, non-color cues, contrast and reduced-motion behavior are checked at runtime; no universal certification claim is made. |
| P8.1-10 | Fresh verifier | A read-only verifier receives only the structured handoff, binds the exact current frontend evidence and returns a current typed status with no stale substitution. |
| P8.1-11 | Runtime eval classification | All 60 structural evals are classified as runtime-required, structurally sufficient, not applicable, future-domain or environment-blocked; unresolved promotion-required runtime evals are zero. |
| P8.1-12 | Static, dependency and security evidence | Full suite, line/branch coverage, Ruff format/check, mypy, dependency-bounded security scans and console/network checks are current; unavailable tools carry only an expiring limitation and no security approval claim. |
| P8.1-13 | Regression and independent review | Phase 2–8 regressions, package/pilot/verifier regressions, exact manifest/attestation and independent capability/frontend/visual/exact-packet reviews all bind the final packet. |

## Promotion rule

`PASS_WITH_LIMITATIONS` and `VERIFIED_CANDIDATE_WITH_LIMITATIONS` require a
current artifact, current runtime/browser/verifier evidence, zero actionable
High/Medium findings, exact packet review and an accepted composition proof.
Level B additionally requires the full rendered/runtime/verification packet.
If both official host-load and the tightly defined observable alternative
causality are unavailable, the honest result remains candidate-only and the
High composition finding stays open.

## Frozen exclusions

The following labels are prohibited: `PRODUCTION_READY`, `RELEASE_READY`,
`SECURITY_APPROVED`, `ACCESSIBILITY_CERTIFIED`, `WCAG_CERTIFIED`,
`ALL_BROWSERS_VERIFIED`, `ALL_VIEWPORTS_VERIFIED`, `UNIVERSAL_FRONTEND_SUPERIORITY`,
`CAUSAL_SUPERIORITY`, and `FULL_HOST_CAUSALITY`.
